# 역할

메인 세션이 맡는다. 서브에이전트로 띄우지 않는다.
직접 구현하기보다 "누가 할지 정하고, 잘 됐는지 확인하고, 상태를 정리한다"가 일이다.

배정·검증·문서 규칙은 armory `war-room` 스킬(SKILL.md와 references)을 따른다. 이 파일에는 스킬 규칙을 옮겨 적지 않는다. 이 프로젝트에서 더 지킬 규칙만 아래 절에 적고, 스킬 규칙과 부딪히면 아래 절이 먼저다.

# 프로젝트별 규칙

- 끝나기 전에 `claude plugin validate .`를 돌린다. mod를 고쳤으면 `claude plugin test .`도 돌린다.
- 공개 레포다. 회사·다른 프로젝트 고유 용어가 없는지 grep으로 확인한다. 회사 코드는 복사하지 않는다. 금지어 목록이 든 검사 스크립트는 레포 밖(스크래치패드)에 둔다.
- 커밋은 사용자가 요청할 때만 한다. 작성자는 레포 로컬 설정(hinyc, noreply 이메일)이다. push는 `gh auth switch -u hinyc`로 바꾼 뒤 하고, 끝나면 원래 활성 계정으로 되돌린다.
- 스킬·mod가 바뀌어 배포할 때는 `plugin.json`·`marketplace.json`의 `version`을 같이 올린다. 안 올리면 설치 캐시가 갱신되지 않는다.
- (템플릿 반영 때 옮김) 기준은 `git diff`로 실제 변경을 확인한 뒤, 파일 목록이 아니라 "무엇이 어떤 상태여야 하나"로 쓴다.
- (템플릿 반영 때 옮김) diff 기반 기준을 쓰기 전에 대상 파일에 커밋 안 된 변경이 있는지 보고, 있으면 바뀔 줄을 이전·새 줄로 적어 판정한다.
- (템플릿 반영 때 옮김) 메인 세션/서브에이전트에 따라 달라지는 규칙은 이 스킬이 띄우는 에이전트(롤·검증·조사·설계)를 모두 확인하고 쓴다.
