# War Room (롤 에이전트 관리)

프로젝트 루트 `war-room/`에 롤(역할)을 정의해 둔다. 일을 받으면 매니저(메인 세션)가 담당 롤의 서브에이전트에게 맡기고, 다른 에이전트가 판정하게 하고, 상황·결정·교훈 문서를 정리한다.

> **일을 받으면 스킬보다 담당 롤을 먼저 찾는다.** 파일 읽기·계획·다른 스킬보다 먼저 한다. 담당 롤이 있으면 필요한 스킬은 그 롤이 쓴다. 답만 하면 되는 질문과, 서브에이전트로 실행 중일 때는 따르지 않는다.
>
> **이 스킬은 세션에서 한 번만 부른다.** 대화가 압축돼 내용이 안 보일 때만 다시 부른다.

`war-room/`에는 `config.json`, `roles/`(`manager.md`, 끌 수 있는 `evaluator.md`, 사용자 롤), `STATUS.md`(현재 상황), `DECISIONS.md`(결정), `LESSONS.md`(교훈), `PLACES.md`(장소 목록: 반복해 쓰는 경로·저장소·이슈·지라 키·문서 URL·명령), `archive/`, `.eval/`(진행 파일·스냅숏, 커밋 안 함)이 있다. 감독 자리를 지정하면 `COMMAND.md`(지휘 보드)와 `commander/`(`commander.md`, 감독 결정 `DECISIONS.md`·감독 교훈 `LESSONS.md`·감독 지시 빈도 `TALLY.md`, 감독 전용 롤 `roles/po.md`·`pm.md`·`tpm.md`)가 생긴다 (`war-room-commander` 스킬). `commander/`는 매니저 배정 대상이 아니다. 비밀값·개인정보는 적지 않고 작업마다 로그를 남기지 않는다. 매니저는 메인 세션, 나머지 롤은 Agent 도구의 서브에이전트다 (`.claude/agents/` 안 씀). `war-room/`이 없는 프로젝트의 일반 작업에는 쓰지 않고, 묻지 않았는데 설치를 권하지도 않는다.

## 언제 무엇을 읽나

아래 파일(모두 `references/` 아래)은 그 상황일 때만 읽는다.

| 상황 | 읽을 파일 |
|---|---|
| 롤에 맡긴다 (모든 등급) | `delegation.md` |
| 등급이 애매하다 | `grade.md` |
| 중·상 (기준·기준선·판정·스냅숏·통과 뒤) | `verify.md` |
| 상 (기준 검토·③ 평가·정형 릴리즈) | `verify-high.md` |
| 판정 실패·멈춤·끝까지 모드 | `retry.md` |
| 평가 롤 꺼짐·없음, QA 롤, 병렬 평가, 플러그인 없음 | `eval-edge.md` |
| 문서 갱신 세부·릴리즈 커밋 | `state-docs.md` |
| 결정을 정할지 물을지, 점검할 결정 | `judgment.md` |
| 평가 에이전트 전용 (매니저는 경로만 준다) | `evaluation.md` |
| 설치·롤 관리 ("롤 추가", "frontend 꺼줘") | `setup.md` (`role-discovery.md`, `role-template.md`) |

| 감독 (`[작업 보고]`) / 작업 세션 (`[감독 지시]`) | `multi-session.md` / `work-session.md`만 읽고 아래 "배정" |

## config.json

- `enabled` `false`(`roles.manager`가 `false`여도 같다): 배정·문서 갱신 없이 평소처럼 일하고 mod 지침도 빠진다.
- `maxAttempts`(기본 1): 시도 상한. 1이면 실패해도 자동 재시도 없이 보고하고 사용자가 재시도를 정한다. 1보다 크면 사용자가 정한 값이라 그 횟수까지 자동 시도한다. 일마다 정할 수 있고, "될 때까지" 뜻이면 무시한다. `suggestRoles`(기본 `true`): `false`면 롤 제안을 하지 않는다.
- `managerDelegateAt`·`managerCompactAt`: `delegation.md` 6절.
- `roles.commander`: 롤이 아니라 감독 자리 스위치다 (`war-room-commander` 스킬). `roles/` 파일이 없어도 경고하지 않는다.
- `roles.<id>`: `false`면 배정에서 뺀다. 없으면 `true`다. 파일만 있고 config에 없으면 켜진 것으로 보고 `true`로 추가한다. config에만 있고 파일이 없으면 배정하지 않고 경고한다.
- `templateVersion`(없으면 1)이 스킬 `template/config.json`과 다르면 반영을 묻는다 (`upgrade.md`). JSON이 틀리면 멈추고 어디가 틀렸는지 알린다. 추측해서 고치지 않는다.

## 배정

일을 받을 때마다 아래 순서로 한다.

1. **설정 읽기**: `config.json`(`enabled: false`면 멈춘다)과 `roles/manager.md`를 읽고 따른다. 세션 첫 배정에서 한 번 `templateVersion`을 비교해 낮으면 반영할지 묻는다 (`upgrade.md` 2절). `STATUS.md`로 진행 중인 일과 이어지는지 보고 관련 결정은 `DECISIONS.md`에서 찾는다 (`(검증 대기)`는 확정이 아니다). `점검할 결정`에 끝난 일의 항목이 있으면 `judgment.md` 4절대로 처리한다. `[감독 지시]`면 `work-session.md`대로 받고 7번은 건너뛴다. `roles.commander`가 켜져 있으면 `COMMAND.md` `## 감독 자리`만 보고 `echo "$CLAUDE_CODE_SESSION_ID"` 값이 `세션 ID`와 같은지로 담당을 확인한다 (`war-room-commander` 스킬 3절). 담당이면 이 배정 절차와 `roles/manager.md` 대신 `commander/commander.md`를 따르고, 아래 2~8번(롤 배정·매니저 직접 처리·문서 갱신)은 하지 않는다.
2. **담당 찾기** (다른 일보다 먼저. `manager`와 `commander/` 아래 감독 롤은 배정 대상이 아니다): 켜진 롤 파일의 `description`·`scope`·`하는 일`·`하지 않는 일`을 요청과 맞춘다. 하나가 맡는다 / 여러 롤에 걸친다 → 롤별로 나눈다 (다른 롤 scope 파일 2개 이하·합계 30줄 이하(바꿀 줄 합계)면 나누지 않고 주 롤이 범위 밖 수정(이유 보고)으로 한다) / 없다 → 알리고, 3개 이상 파일을 읽는 조사는 `Explore`에, 그 밖의 일은 하 등급이라도 매니저가 직접 하지 않고 임시 작업 에이전트(`general-purpose`, `model: sonnet`, 담당 `manager`, 세션마다 동시 최대 4개)에 맡긴다. 예외는 매니저만 쓰는 파일(STATUS 정리, 승인된 교훈 넣기)뿐이다 (`delegation.md` 5절). 감독 세션은 보드에 맞는 작업 세션이 있으면 `[감독 지시]`로 넘기고 없을 때만 임시 작업 에이전트에 맡긴다 (직접 하지 않는다). 답만 하는 질문은 배정 없이 답한다.
3. **등급·요구 수준**: 등급은 아래 "등급 판정"으로 정한다. 요구 기준은 사용자가 말한 수준, 없으면 매니저 초안이고 `명령 → 기대 결과`를 붙인다 (`verify.md` 1절). 중·상은 맡기기 전에 기준선을 잰다. 상은 기준 검토·수치 준비도 한다 (`verify-high.md`). 평가 롤이 꺼짐·없음이면 `eval-edge.md`.
4. **알리기**: `→ <롤> 롤에 맡깁니다 (<요약>, 등급 <하|중|상>, 기준 n개, 최대 m회, 에이전트 n개 예정)` 다음 줄에 `정한 것: <결정>; <결정>` (`judgment.md` 2절). 예정보다 더 띄우면 이유 한 줄을 알린다.
5. **맡기기**: 요청에 위치가 빠졌으면 ("그 파일", "그 이슈", "지라 업데이트") 요청 표현으로 `PLACES.md`를 grep해 걸린 줄의 실제 위치를 프롬프트 `## 범위`·`## 관련 파일`에 넣는다. 안 걸리거나 여러 줄이 걸리면 추측하지 않고 사용자에게 묻는다 (`delegation.md` 1절). Agent 도구, 종류 `general-purpose`, `model`은 롤의 `model`(없으면 생략), `description` `<롤 id>: <요약>`, `prompt`는 `delegation.md`의 고정 칸 템플릿. 병렬(상)은 공유 약속을 정할 수 있을 때만 동시에 띄운다 (`delegation.md` 4절). 구현 롤은 커밋하지 않는다 (예외: 릴리즈 담당 롤, 작업 세션은 `multi-session.md`).
6. **검증 → 반복**: 보고의 `가정한 것`·`모호했던 것`을 먼저 읽는다 (`delegation.md` 2절). 구현한 에이전트와 매니저가 아닌 읽기 전용 에이전트(`armory:evaluator`)가 판정하며 방식은 아래 표다. 프롬프트에 `## 매니저가 정한 것` 칸을 넣는다 (`judgment.md` 4절). 띄우기 직전·직후 스냅숏을 비교하고 오래 걸리는 명령은 매니저가 한 번 돌려 기록한다 (`verify.md` 3·4절). `등급 올림`이나 사후 점검에 신호·조건이 있으면 그 등급으로 다시 판정한다. 범위 밖 수정은 이유를 확인한다. 주관 기준·⚠는 통과 뒤 사용자에게 확인받는다. 실패하면 `retry.md` (기본은 보고 뒤 질문).
7. **문서 갱신** (매니저만. `state-docs.md`): `STATUS.md`는 **바뀐 절만** Edit로 고친다. 진행 중 줄은 `롤 · 작업 · 등급 · 시도 n/최대 · 남은 실패 기준 · 기준이 적힌 곳`이고 시도마다 스냅숏 전에 고친다. 결정은 `DECISIONS.md`에, 중·상에서 매니저가 정한 결정은 `## 점검할 결정`에 (`judgment.md` 3절), 막힌 일은 `LESSONS.md`에, 반복 신호는 `## 롤 후보`에 쌓는다 (`role-split.md`). 확인된 위치(사용자가 말하거나 답한 위치, 작업에서 근거와 함께 쓰여 확인된 위치)를 다시 쓸 것 같으면 매니저가 판단해 묻지 않고 `PLACES.md` 맞는 절에 `이름(부르는 말) · 종류 · 위치 · 쓰는 때 · 확인한 날` 한 줄을 넣고, 보고에 `장소 목록: <부르는 말> 추가|고침` 한 줄을 붙인다 (같은 부르는 말 줄이 있으면 그 줄을 고친다. 추측한 값과 비밀은 적지 않는다. 임시 폴더·일회성 브랜치처럼 한 번 쓰고 말 위치도 적지 않는다).
   - **순서** (모든 등급): 구현(커밋 없음) → 검증·평가 → 스냅숏 비교 → 통과 → 문서 갱신 → 이어받기 점검 → 커밋(사용자가 요청하면 매니저가 구현과 문서를 한 커밋으로). 하 등급은 기계 검사·사후 점검 뒤에 갱신한다. 릴리즈는 정형이면 `verify-high.md` 7절, 아니면 `state-docs.md` 5절을 따른다.
   - **이어받기 점검**: 문서 갱신 뒤 매니저가 새 세션이 STATUS.md와 DECISIONS.md만 읽고 지금 상태·다음 할 일·점검할 결정을 말할 수 있는지 본다.
8. **보고**: 결과·바뀐 것·남은 일, `매니저가 정한 것`(하 등급은 여기에만), 결정 점검("결정 n개 점검 통과", 재검토는 근거와 함께 묻는다). 중 명령 판정은 `점검할 결정`도 적는다.

롤 없이 직접·임시 에이전트로 처리해도 6·7번을 한다.

## 등급 판정 (하·중·상)

파일 수가 아니라 **검증 신호**로 위에서부터 보아 처음 걸리는 것으로 정한다. 애매하면 높은 쪽이다. 세부·예는 `grade.md`.

1. **사용자가 정한 등급**: 따르고 알리기 줄에 적는다. 하이면 사후 점검을 하고 걸리면 혼자 올리지 않고 묻는다.
2. **무조건 상** (낮추지 않는다): 릴리즈·push·배포 / 스킬·롤 문서 규칙(3번의 상) / mod 지침(시스템 프롬프트 문구) 수정 / 여러 롤 병렬 / 신호 있는 변경 파일 5개 이상 / 삭제·마이그레이션 (롤 파일 삭제 포함) / 공개 노출 / 권한·보안
3. **스킬·롤 문서 규칙** (테스트가 없다): 뜻 그대로인 문구 정리 → 하, 규칙의 뜻이 바뀜 → 중, 등급·검증·배정 흐름 변경 → 상, 애매하면 중. 예외: 승인된 교훈 문장을 그대로 넣는 롤 문서 수정은 하 (grep 확인).
4. **검증 신호** (하나라도 있으면 중, 하나도 없으면 하):
   - 복잡한 데이터: 스키마·타입·변환·파싱·직렬화·상태 구조 변경
   - 3단계 이상 데이터 전달: 값이 세 곳 이상 거쳐 흐르는 경로 변경
   - 로직 변경으로 같은 입력의 출력이 달라진다 (전후 테스트 통과나 전후 출력 비교가 같으면 아니다)
   - 약속 변경: 다른 파일·롤이 기대는 함수 모양·공개 형식·이벤트 이름·설정 키 변경
   - 동작이 바뀌는데 그 동작을 테스트가 덮지 않는다

| 등급 | 판정 방식 |
|---|---|
| 하 | 기계 검사 (아래) |
| 중 | 기준이 전부 `명령 → 기대 결과`이고 결과가 판단 없이 비교되면 매니저가 명령을 돌려 판정하고 `git diff`로 범위·등급 올림 신호를 본다. 하나라도 읽고 판단하는 기준이면 `haiku` 검증 에이전트가 모든 기준을 판정한다. 스킬·롤 문서의 규칙 뜻이 바뀌는 일은 판단 기준이 반드시 하나다 |
| 상 | 기준 검토(`haiku` 한 번) → 구현 → 평가 롤 켜짐이면 시도마다 ③ 한 번, 꺼짐·없음이면 기준별 판정 → 되돌리기 어려운 단계 전 사람 승인. 정형 릴리즈는 기준 검토·평가 없이 매니저가 명령으로 확인한다 |

### 하 등급 (이 문서만으로 끝낸다)

- **하 조건** (모두): 무조건 상에 안 걸린다 / 검증 신호가 없다 (스킬·롤 문서는 3번 규칙) / 확인 방법이 있다.
- **기계 검사**: 돌릴 명령(테스트·린트·validate·grep)의 결과로 판정한다. 없으면 `git diff`로 바뀐 줄이 요청 범위 안이고 신호가 없는지 본다.
- **사후 점검** (끝낸 직후, 건너뛰지 않는다): `git diff`에 검증 신호나 무조건 상 조건이 생겼으면 그 등급으로 올려 판정한다.
- **매니저 직접 처리** (감독 세션에는 적용하지 않는다. 감독은 하 등급도 직접 하지 않는다): 담당 롤이 있으면 하라도 롤에 맡기고, 담당 롤이 없으면 하라도 임시 작업 에이전트에 맡긴다 (`delegation.md` 5절). 매니저가 직접 하는 예외는 둘뿐이다: (a) 매니저만 쓰는 파일 (STATUS 정리, 승인된 교훈 넣기) (b) 바꿀 문장·값이 정해진 하 일이고 파일 2개 이하 ("정해진": 사용자가 그대로 말했거나 승인했거나 답이 하나뿐인 경우). 직접 한 일은 STATUS 최근 완료에 등급과 파일 수를 적고 7번대로 갱신한다.

## 하지 않는 것

- 담당 롤이 있는 일을 롤 에이전트 없이 매니저가 직접 하기 (예외: 사용자가 직접 하라고 했을 때, 하 등급 절의 직접 처리 예외)
- 자기 검토 금지: 구현한 에이전트나 매니저가 자기 결과를 판정하기 (예외: 하 등급 기계 검사, 중 명령 판정, 정형 릴리즈 확인, 이어받기 점검. 판단이 아니라 명령 결과 비교나 자기 기록 점검이다)
- 롤 파일·config를 확인 없이 크게 바꾸기 (켜고 끄기는 예외), 서브에이전트에게 `war-room/` 문서 쓰게 하기 (평가 에이전트의 진행 파일, 릴리즈 담당 롤이 매니저가 갱신한 문서를 커밋에 넣는 것, 감독 롤 pm이 `COMMAND.md`(크기 정리 때 `archive/COMMAND-YYYY-MM.md` 포함)·`PLACES.md`를 쓰는 것은 예외. 롤 에이전트는 `PLACES.md`를 읽을 수만 있다), 사후 점검 건너뛰기
- 템플릿 반영을 묻지 않고 `war-room/` 파일 고치기, 프로젝트별 규칙·사용자 롤을 템플릿으로 덮기
- 감독 세션이 사용자 대신 어려운 결정 승인하기 (`multi-session.md` 7절)
