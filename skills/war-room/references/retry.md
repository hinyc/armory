# 판정이 실패했을 때 (다시 맡기기 · 멈추기 · 못 미침 보고)

판정이 통과하면 이 문서를 읽지 않는다.

## 1. 다시 맡기기

다음 시도는 **같은 에이전트에게 "다시 해"라고 하지 않는다.** 실패 원인에 따라 고른다.

| 실패 원인 | 다음 시도 |
|---|---|
| 일부 기준만 못 맞춤, 접근은 맞음 | 같은 롤의 **새 에이전트**에게 현재 결과 + 검증 보고(판정 근거)를 주고 고치게 한다 |
| 접근 자체가 틀림 | 같은 롤의 새 에이전트에게 **다른 접근**을 지시한다. 지난 시도에서 무엇을 해 봤고 왜 안 됐는지 적는다 |
| 롤이 맞지 않았음 (범위 밖 지식 필요) | 맞는 다른 롤에 맡긴다. 없으면 하 등급 일만 매니저가 직접 하고, 하가 아니면 임시 작업 에이전트에 맡기거나 롤 추가를 제안한다 |
| 요구가 모호해 판정이 갈림 | 시도하지 말고 사용자에게 기준을 다시 묻는다 |

- `## 지난 시도`에는 판정 에이전트가 찾은 실패 내용(실패 기준·갈래, 근거)만 넣는다. 구현 에이전트의 설명·자기 평가는 넣지 않는다. 매니저가 덧붙이는 것은 `이번에 바꿀 것` 한 줄이다 (`delegation.md` 3절).
- 판정 1번이 실패면 실패 1번으로 센다.
- 다른 접근으로 다시 할 때는 Agent를 `isolation: "worktree"`로 띄워 지금까지 가장 좋은 결과를 지킨다. 통과한 쪽만 작업 폴더에 반영한다.
- 시도마다 `STATUS.md` 진행 중에 `시도 n/최대 · 남은 실패 기준`을 적는다 (스냅숏 전에. 다른 절은 통과 뒤에 쓴다).
- 시도마다 기준별 통과 수를 기록하고, 가장 많이 통과한 시도를 "최고 결과"로 둔다.
  - 예외: 상 등급이고 evaluator 켜짐이면(중은 해당 없음) 통과 수 대신 **다섯 갈래의 ✗ 개수**를 기록하고 ✗가 가장 적은 시도를 최고 결과로 둔다. 같으면 ✓가 많은 시도, 그것도 같으면 나중 시도. 갈래 전체를 세므로 기준 수가 시도마다 달라도 비교할 수 있다. `STATUS.md`에는 `남은 ✗ n개(갈래)`로 적는다.

### 2번 실패하면: 기준·설계 다시 보기

같은 일이 **2번 실패하면** 3번째를 맡기기 전에 매니저가 기준과 설계를 다시 본다. 셋을 확인한다: 두 실패의 원인이 같은 기준·같은 갈래인가, 기준끼리 부딪히는가, 기준이 모호해 판정이 갈렸는가.
- 기준·설계 문제로 보인다 → 재시도하지 않고 사용자에게 묻는다. 무엇이 왜 막혔는지와 고칠 안 2개를 낸다.
- 실행 문제(구현 실수)로 보인다 → 3번째를 맡기고 이유를 한 줄 알린다.

끝까지 모드에서도 다시 보기는 한다. 다만 묻지 않고 접근을 바꾼다. 예외: 결과가 "기준끼리 부딪힘"이나 "기준이 모호함"이면 사용자만 정할 수 있으므로 묻는다 (구현을 바꿔도 기준이 풀리지 않기 때문이다).

## 2. 멈출 때

아래 중 하나면 더 시키지 않고 멈춘다.

- 시도 횟수가 `maxAttempts`에 닿았다.
- 두 번 연속 통과한 기준 수가 늘지 않았다. 예외: 상 등급이고 evaluator 켜짐이면 ✗ 개수가 줄지 않은 것을 뜻한다.
- 실패 원인이 시도로 풀 수 없는 것이다: 라이브러리·플랫폼의 한계, 없는 API·권한, 서로 부딪히는 기준.
- 한 시도가 예상보다 훨씬 오래 걸리고 끝이 보이지 않는다. 진행 상황을 알리고 계속할지 사용자에게 묻는다.

멈추면 **최고 결과로도 수준에 못 미친다고 분명히 말하고 대안을 2개 이상 낸다** (3절).

### 끝까지 모드

정해진 문구가 아니라 **뜻으로 판단한다.** "시간·횟수가 얼마나 들든 결과를 내라"는 뜻이면 끝까지 모드다.

- 해당하는 예 (이것만이 아니다): "될 때까지", "무조건 완성해", "끝까지 해", "포기하지 마", "몇 번이 걸리든", "시간 걸려도 괜찮아", "완성될 때까지 돌려", "안 되면 될 때까지 다시", "결과 나올 때까지 멈추지 마"
- 해당하지 않는 예: "꼭 해줘", "잘 해줘", "급해". 강조이거나 일정에 대한 말이고 횟수 제한을 풀라는 뜻이 아니다.
- 애매하면 기본 규칙으로 한다. 멈출 때 내는 대안에 "끝까지 계속 시도"를 하나로 넣어 사용자가 고를 수 있게 한다.
- 끝까지 모드로 판단했으면 시작할 때 알린다. 예: `→ 끝까지 모드: 통과할 때까지 반복합니다`

동작:
- `maxAttempts`와 위 멈춤 조건을 쓰지 않는다. 오래 걸려도 계속할지 묻지 않는다.
- 나아지지 않는 반복이나 한계에 부딪히면 멈추는 대신 **접근을 바꾼다.** 같은 접근을 되풀이하지 않는다 (다른 구현 방식, 다른 라이브러리, 다른 롤, 문제를 더 작게 나누기). 해 본 접근은 `STATUS.md` 진행 중에 목록으로 남긴다.
- 사용자만 줄 수 있는 것(권한, 비밀값, 서로 부딪히는 기준 중 선택, 모호한 기준의 뜻)이 필요할 때만 묻는다. 2번 실패 뒤 다시 보기는 한다. 답을 받으면 바로 이어서 반복한다.
- 시도 3번마다 한 줄로 알린다: `시도 n · 통과 기준 j/m · 지금 접근`. 상 등급이고 evaluator 켜짐이면 `시도 n · 남은 ✗ k개 · 지금 접근`. 알리기만 하고 멈추지 않는다.
- 사용자가 멈추라고 하거나 기준을 바꾸면 따른다. 이 지시는 그 일에만 적용하고 다음 일은 기본 규칙이다.

## 3. 못 미칠 때 보고 (대안 필수)

통과 못 했는데 "거의 됐다"고 포장하지 않는다. 아래를 모두 적는다.

```
요구 수준을 맞추지 못했어요. (시도 n번)

- 최고 결과: 시도 k — 기준 m개 중 j개 통과 (상이고 evaluator 켜짐이면 ✗ n개, 갈래별 판정). 현재 작업 폴더에 반영됨 | worktree <경로>에 있음
- 못 맞춘 기준: <기준> — 이유: <검증 근거로 확인한 원인>
- 더 시도해도 안 될 거라고 보는 이유: <같은 원인 반복 / 한계 근거>

대안
1. (추천) <기준을 이렇게 낮추면 지금 결과로 충족>
2. <다른 방식: 무엇을 바꾸면 되는지, 드는 비용>
3. <사용자가 정해야 할 것 / 필요한 자원>
```

- 대안은 최소 2개이고 그중 하나를 추천한다. 대안마다 무엇을 포기하거나 더 들이는지 적는다.
- 사용자가 대안을 고르면 `DECISIONS.md`에 적고, 정해진 기준으로 다시 반복을 시작한다.
- 같은 이유로 막힌 일은 `LESSONS.md`에 적는다.
