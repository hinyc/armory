# 템플릿 업데이트 반영

플러그인을 업데이트하면 스킬 규칙은 바로 바뀌지만, 설치 때 프로젝트에 복사한 파일(`roles/manager.md`, `roles/evaluator.md`, `config.json`, STATUS 절 제목, `.gitignore` 줄)은 옛 내용 그대로 남는다. 비교와 반영은 스크립트가 하고, 매니저는 결과 요약만 읽는다 (파일을 직접 열어 비교하지 않는다).

## 1. 버전

- 템플릿 버전: 이 스킬 `template/config.json`의 `templateVersion`(정수). 템플릿 파일이 바뀔 때만 1씩 올린다. 플러그인 버전과 따로 세므로 템플릿이 그대로인 업데이트에서는 묻지 않는다.
- 프로젝트 버전: 프로젝트 `war-room/config.json`의 `templateVersion`. 없으면 1 (이 값이 생기기 전 설치).

## 2. 언제 묻나

- **세션에서 처음 배정할 때 한 번만** 두 값을 비교한다. 같은 세션의 다음 요청에서는 비교하지 않는다. `enabled: false`면 비교하지 않는다.
- 프로젝트 = 템플릿이면 아무것도 하지 않는다. 프로젝트가 더 크면 "플러그인을 업데이트하세요" 한 줄만 알린다.
- 프로젝트 < 템플릿이면 `python3 <이 스킬>/scripts/upgrade.py check <프로젝트>/war-room`을 돌리고, 출력 요약을 붙여 한 번 묻는다 (AskUserQuestion): `war-room 템플릿이 업데이트됐어요 (프로젝트 n → 템플릿 m). 이 프로젝트에 반영할까요?`
  - `지금 반영` → 3절. 끝나면 원래 요청을 이어서 한다.
  - `이번엔 건너뛰기` → 기록하지 않는다. 다음 세션에서 다시 묻는다.
  - `이 버전은 묻지 않기` → config에 `"skipTemplateVersion": m`을 넣는다. 템플릿이 m보다 올라가면 다시 묻는다.
- 묻지 않고 건너뛴다: 답을 받을 수 없는 실행(예약 실행, 서브에이전트), 감독 지시를 받은 연결 워크트리 세션(`multi-session.md` 3절. 본 체크아웃 세션에서 반영한다), `skipTemplateVersion`이 템플릿 버전 이상.
- 사용자가 "war-room 업데이트", "워룸 템플릿 반영"이라고 하면 버전과 상관없이 check부터 한다.

## 3. 반영

1. `python3 <이 스킬>/scripts/upgrade.py apply <프로젝트>/war-room [--drop 1,3]`
   - check가 번호를 붙인 "옮길 사용자 문장" 중 사용자가 버리라고 한 번호만 `--drop`에 넣는다. 고르지 않으면 모두 옮긴다 (지우는 것보다 되돌리기 쉽다).
   - 종료 코드 3이면 멈추고 출력 내용(미커밋 변경, `# 프로젝트별 규칙` 제목 없음, JSON 오류)을 사용자에게 알린다. 추측해서 고치지 않는다.
2. 판정: 출력의 ✓ 줄이 모두 ✓면 하 등급으로 끝낸다. 옮긴 사용자 문장이 있으면 중으로 올려 `armory:evaluator`(model `haiku`)가 옮긴 문장이 새 템플릿 규칙과 부딪히는지만 판정한다.
3. `DECISIONS.md`에 항목을 추가한다: `## <날짜> · war-room 템플릿 n → m 반영` · 결정: 바뀐 파일, 옮긴 문장 수 · 정한 사람: 사용자.
4. 보고: 바뀐 파일과 옮긴 문장. 커밋은 사용자가 요청할 때 한다.

## 4. 스크립트가 바꾸는 것

| 파일 | 템플릿으로 바꾸는 부분 | 그대로 두는 부분 |
|---|---|---|
| `roles/manager.md` | `# 프로젝트별 규칙` 제목 위 전부 (frontmatter 포함) | `# 프로젝트별 규칙` 절 전체 |
| `roles/evaluator.md` (있을 때만) | 같음 | `# 프로젝트별 규칙` 절, frontmatter `model` 값 |
| `config.json` | 템플릿에만 있는 키 추가, `templateVersion` | 이미 있는 키의 값, `roles` 전체 |
| `STATUS.md` | 빠진 `## ` 절을 템플릿 순서 자리에 `- 없음`으로 추가, 절 제목 괄호 설명 | 모든 절의 내용 |
| 프로젝트 `.gitignore` | `war-room/.eval/` 줄이 없으면 추가 | 나머지 |
| 사용자가 만든 롤, `DECISIONS.md`·`LESSONS.md` | 바꾸지 않는다 | 전부 |

- 롤 문서의 `# 프로젝트별 규칙` 위쪽에서 새 템플릿에 없는 줄은 `template-history/<롤>.txt`(지난 템플릿 문장 목록)와 대조해 가른다. 목록에 있으면 옛 템플릿 문장이라 버리고, 없으면 사용자 문장이라 `# 프로젝트별 규칙` 절 끝에 `- (템플릿 반영 때 옮김) <원문>`으로 옮긴다.
- 반영 전 사본을 임시 폴더에 남기고 경로를 출력한다. `evaluator.md`가 없으면 만들지 않는다 (평가 롤 추가 제안은 SKILL.md 배정 3번).

## 5. 템플릿을 고치는 쪽 (플러그인 개발)

- `template/` 아래 파일을 바꾸면 `template/config.json`의 `templateVersion`을 1 올린다.
- 기본 롤 템플릿을 바꾸면 커밋 뒤 저장소 루트에서 `python3 skills/war-room/template-history/build.py`를 돌려 지난 문장 목록을 다시 만든다. 빠지면 옛 템플릿 문장이 사용자 문장으로 잘못 옮겨진다.
- 프로젝트가 채울 부분은 `# 프로젝트별 규칙` 절에만 둔다. 템플릿에 새 파일이나 기본 롤을 더하면 `scripts/upgrade.py`와 4절 표를 같이 고친다.
