# 평가 롤 가장자리 상황 (그 상황일 때만 읽는다)

평가 롤이 켜져 있고 QA 롤·병렬이 없는 보통의 경우에는 읽지 않는다 (`verify-high.md`가 전부다).

## 1. 평가 롤 켜짐·꺼짐·없음

| 상태 | 판단 | 동작 |
|---|---|---|
| 꺼짐 | `roles.evaluator: false` (롤 파일 유무 무관) | 평가 롤을 쓰지 않는다. 기준별 판정으로 돌아간다 (2절). 진행 파일을 쓰지 않으므로 띠도 안 뜬다 |
| 켜짐 | `false`가 아니고(`true`이거나 키 없음) `roles/evaluator.md`가 있음 | 상은 `verify-high.md`대로 평가한다. 중은 `verify.md`의 판정이고 스냅숏만 같다 |
| 없음 (기존 설치) | `false`가 아니고 `roles/evaluator.md`가 없음 | 경고하고 그 배정은 꺼짐과 같이 마친다. 파일이 없는 것을 처음 안 배정에서 한 번 "평가 롤을 추가할 수 있어요"라고 알리고, 승인하면 템플릿에서 `roles/evaluator.md`를 복사하고 config에 `"evaluator": true`, `.gitignore`에 `war-room/.eval/`을 넣는다. 거절하면 `DECISIONS.md`에 적고 다시 묻지 않는다 |

- `evaluator`는 `manager`와 달리 끄기·삭제할 수 있다.
- 기존 설치에 추가할 때 검증·QA 롤이 있으면 두 롤의 경계를 양쪽 `하지 않는 일`에 적자고 함께 제안한다.
- **두 축은 별개다.** 평가 롤 켜짐(config와 롤 파일)과 에이전트 종류(armory 플러그인 유무)는 따로 본다.
  - 플러그인이 있으면 평가 롤이 꺼졌거나 없어도 검증·기준 검토 에이전트는 `armory:evaluator`로 띄우고 다섯 갈래 대신 기준별로 판정한다.
  - 플러그인이 없으면(다른 도구로 설치) `general-purpose`로 되돌리고 알린다. 이때 읽기 전용은 프롬프트 규칙과 스냅숏 비교(`verify.md` 4절)에만 기댄다.
  - 플러그인 유무는 사용 가능한 에이전트 종류에 `armory:evaluator`가 있는지로 본다.

## 2. 상에서 평가 롤이 꺼짐·없음일 때

- 상도 기준별로 판정한다 (`verify.md` 2절의 검증 에이전트 프롬프트). 에이전트는 기준 검토 1 + 시도마다 기준별 검증 1이다. model은 판정이 상 등급 규칙대로 롤 파일의 `model`(기본 `sonnet`)이고 기준 검토는 늘 `haiku`다.
- 켜진 롤 중 검증·QA를 맡는 롤이 있으면 판정을 그 롤에 맡긴다 (플러그인이 있으면 `armory:evaluator` 종류로 띄우고 그 롤 파일을 프롬프트에 넣는다). 없으면 `verify.md`의 프롬프트로 새 에이전트를 검증 전용으로 띄운다. 이 위임은 판정에만 해당하고 기준 검토는 `verify-high.md` 2절대로 새 에이전트가 한다.
- 이 검증 에이전트도 `evaluation.md`를 읽지 않고, 판정 규칙은 `verify.md`의 프롬프트가 전부다.
- 병렬이면 롤별 판정이 모두 통과한 뒤 롤 사이 부작용을 보려고 매니저가 전체 테스트를 한 번 더 돌린다.

## 3. 이미 검증·QA 롤이 있는 프로젝트 (평가 롤 켜짐)

- evaluator가 켜져 있으면 평가는 evaluator가 맡는다. QA 롤에 판정을 맡기는 것은 evaluator가 꺼졌거나 없을 때만이다.
- 사용자가 만든 QA 롤의 `완료 기준`·`일하는 방식`은 평가가 기준 갈래에 더해 쓴다. 평가 에이전트는 롤 파일을 `refs`로 읽지 않으므로, 매니저가 그 두 절을 ③ 프롬프트 `## 대상`의 QA 롤 줄에 옮겨 넣는다.

## 4. 여러 롤에 나눈 일 (병렬은 등급 상)

- 평가는 롤마다 따로 한다 (롤마다 ③). 기준선은 모든 구현을 맡기기 전에 한 번 떠서 모든 롤의 ③에 같이 넣고, 롤마다 다른 변경 전 수치는 `## 기준선`에 롤별로 적는다. 스냅숏은 모든 롤의 구현이 돌아온 뒤 한 번에 뜬다 (`verify.md` 4절).
- 진행 파일과 오래 걸리는 명령 기록도 롤마다 따로 둔다 (`war-room/.eval/<롤 id>.json`, `<롤 id>.long-run.txt`). 동시에 돌아도 서로 덮어쓰지 않는다.
- 평가 롤이 켜져 있으면 병렬 뒤 매니저의 전체 테스트 재실행은 하지 않는다 (각 ③이 모든 구현이 돌아온 뒤 부작용 갈래로 전체 테스트를 돌려 중복이다). 맡기기 전의 공유 약속은 `delegation.md` 4절.

## 5. 플러그인 없음

armory 플러그인이 없고 war-room 폴더만 있으면 모든 검증·평가·기준 검토 에이전트를 `general-purpose`로 띄우고 알린다. `Edit`·`Write`를 막을 수 없으므로 프롬프트의 읽기 전용 규칙과 스냅숏 비교가 유일한 확인이다.
