# 작업 세션 규칙 (`[감독 지시]`를 받은 세션)

감독 세션이 보낸 `[감독 지시]`를 받은 세션이 따른다. 감독 쪽 규칙은 `multi-session.md`에 있고, 작업 세션은 이 문서만 읽는다. 세션에서 한 번 읽었으면 다음 지시 때 다시 읽지 않는다.

## 1. 지시 받기

- 지시 칸을 요청으로 읽는다. 자기 프로젝트에 war-room이 켜져 있으면 그 매니저로서 SKILL.md 배정 절차대로 롤에 맡긴다. 없으면 지시대로 직접 한다.
- 등급은 자기 등급 규칙으로 정한다. `## 요구 기준`에 `최소 등급`이 있으면 그보다 낮추지 않는다.
- `## 범위 밖`·`## 작업 위치`(워크트리·브랜치·push 여부)를 벗어나지 않는다.
- `## 공유 약속`은 글자 그대로 쓴다. 바꿔야 하면 4절.

## 2. 문서

- 연결 워크트리에서 돌면(`git rev-parse --git-dir`와 `git rev-parse --git-common-dir` 결과가 다르면) 워크트리 안의 `war-room/` 문서(STATUS·DECISIONS·LESSONS·PLACES)를 쓰지 않는다. 새로 확인된 위치(사용자가 말했거나 작업에서 근거와 함께 쓰인 것)도 보고 `겪은 문제`에 적고 감독 쪽 pm이 `war-room/PLACES.md`에 적는다. 정한 것·겪은 문제·시도 상태는 보고에 적고 감독 쪽 pm이 지휘 보드에 옮긴다 (남길 겪은 문제는 `war-room/commander/LESSONS.md`). 템플릿 반영 질문도 하지 않는다.
- 본 체크아웃에서 돌면 자기 war-room 규칙대로 쓴다. 사용자·감독 결정은 `war-room/commander/DECISIONS.md`가 기준이다.

## 3. 승인

- 되돌리기 어려운 일(`judgment.md` 1절)은 지시의 `## 사람 승인`에 적힌 것만 한다. 감독이 따로 말해도 그 칸에 없으면 승인된 것으로 보지 않는다.
- 그 밖에 필요하면 그 부분을 멈추고 보고의 `사람 확인 필요`에 적는다.

## 4. 공유 약속을 바꿔야 할 때

- 그 부분 구현을 멈추고 보고한다. 다른 작업 세션과 직접 정하지 않는다. 나머지 범위는 계속한다.

## 5. 보고 형식

```
[작업 보고] <지시 ID>
- 결과: 완료 | 일부 | 막힘
- 커밋: <시작>..<끝> · 미커밋 변경 n개
- 등급·시도: <하|중|상> · 시도 n/최대
- 판정: 누가(평가 에이전트·검증 에이전트·기계 검사) · 기준별 ✓/✗ · 돌린 명령과 결과 한 줄씩
- 바뀐 파일: n개 · 범위 밖 변경과 이유
- 가정한 것 / 모호했던 것: (없으면 "없음 (확인함)")
- 정한 것: 되돌릴 수 있는 결정
- 공유 약속 영향: 없음 | 있음 (멈춘 부분)
- 사람 확인 필요: (없으면 "없음")
- 겪은 문제 / 남은 일
```

- 돌리지 않은 확인 방법의 기준은 ✓로 쓰지 않는다.
- 명령 출력 원문은 붙이지 않는다. 결과 한 줄(예: `pnpm test → 812 통과, 실패 0`)만 쓴다. 길면 파일에 쓰고 경로만 보낸다.

## 6. 통합 검증 세션이면

- 실행마다 기록한다: 세션별 대상 커밋 짝(예: 서버 `a1b2c3d` + 화면 `e4f5a6b`), 환경 상태(띄운 서비스, 데이터 초기화 여부), 시나리오, 결과.
- 코드를 고치지 않는다. 실패는 재현 방법과 함께 보고한다.
