# 롤 분리 제안

매니저가 직접 하던 일이나 한 롤에 몰린 일을 보고, 따로 롤로 떼어 낼지 사용자에게 묻는다. **묻기만 한다. 승인 없이 롤을 만들지 않는다.**

## 신호

일이 끝날 때마다(배정 7번 "문서 갱신" 때) 아래를 확인한다.

| 신호 | 기준 | 어디서 보나 |
|---|---|---|
| **자주** | 맞는 롤이 없어 매니저가 직접 한 같은 종류의 일이 3번 | `STATUS.md` 롤 후보 |
| **길게** | 한 번의 요청이 단계 5개 이상이거나, 시도를 3번 넘게 했거나, 여러 세션에 걸침 | 이번 작업 |
| **참고할 것이 많음** | 같은 문서·규칙·명령을 일할 때마다 다시 찾아 읽거나 설명해야 함. 롤 없는 영역의 `LESSONS.md` 항목이 3개 이상 | 이번 작업, `LESSONS.md` |
| **롤이 너무 큼** | 기존 롤 하나가 서로 다른 두 종류의 일을 맡음. 롤 파일이 150줄을 넘음. 그 롤의 교훈이 두 갈래로 나뉨 | 롤 파일, `LESSONS.md` |

- "같은 종류"는 문구가 아니라 다루는 영역(경로·기술·업무)으로 판단한다.
- 신호 하나만 커도 되고, 둘 이상이 함께 보이면 더 먼저 묻는다.

## 신호 쌓아 두기

`STATUS.md`의 `## 롤 후보`에 적는다. STATUS를 다시 쓸 때도 이 절은 이어서 남긴다.

```markdown
## 롤 후보
- 데이터 마이그레이션 (scripts/migrate/**) · 직접 처리 2회 · 마지막 2026-11-03 · 참고: docs/db.md
```

- 롤을 만들었거나 사용자가 거절한 후보는 지운다.
- 30일 넘게 다시 안 나온 후보는 지운다.

## 묻는 방법

- 사용자에게 결과를 보고한 **뒤에** 한 번 묻는다. 일하는 중간에 끊지 않는다.
- AskUserQuestion으로 묻는다. 질문에 신호와 롤 초안을 함께 보여준다.
- **질문 맨 아래에 끄는 방법을 항상 붙인다**: `(이 질문은 war-room/config.json의 "suggestRoles": false로 끌 수 있어요)`. 빼지 않는다.

```
"데이터 마이그레이션" 일을 매니저가 3번 직접 했고, 매번 docs/db.md와 마이그레이션 규칙을 다시 읽었어요.
롤로 분리할까요?

초안
- name: migration
- description: DB 스키마 변경·데이터 이전 스크립트를 맡는다
- scope: scripts/migrate/**, db/schema/**
- refs: docs/db.md
- 하지 않는 일: API 코드 수정 → backend

(이 질문은 war-room/config.json의 "suggestRoles": false로 끌 수 있어요)
```

선택지
1. 분리 (추천일 때 표시)
2. 초안을 고쳐서 분리
3. 지금은 안 함
4. 앞으로 묻지 않기 → `suggestRoles`를 `false`로 바꾸고, 다시 켜는 방법(`true`로 되돌리기)을 알린다

- **분리하면**
  - `references/role-template.md` 형식으로 롤 파일을 만들고 config에 `true`로 넣는다.
  - 그동안 반복해서 읽은 문서는 `refs`에, 관련 `LESSONS.md` 항목은 해당 절에 옮긴다.
  - 기존 롤을 나눈 것이면 원래 롤의 `하는 일`·`scope`에서 뺀다.
  - 분리한 이유는 `DECISIONS.md`에 적는다.
- **안 한다고 하면**
  - "X 롤 분리 안 함 · 이유"를 `DECISIONS.md`에 적는다.
  - 같은 후보는 다시 묻지 않는다. 단, 신호가 처음 물을 때의 2배가 되면 한 번 더 묻는다.

## 끄기

`config.json`의 `"suggestRoles": false`면 신호를 쌓지도 묻지도 않는다. 사용자가 "롤 분리 묻지 마"라고 하면 이 값을 바꾼다.
