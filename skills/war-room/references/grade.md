# 등급 세부 (SKILL.md "등급 판정" 표가 애매할 때만 읽는다)

표의 순서(사용자 등급 → 무조건 상 → 스킬·롤 문서 → 검증 신호 → 하)는 SKILL.md가 정한다. 여기는 정의의 세부와 예다. 등급은 파일 수가 아니라 검증 신호로 정하고, 애매하면 높은 쪽이다.

## 1. 검증 신호 세부

- 1 복잡한 데이터: 스키마·타입·변환·파싱·직렬화·상태 구조를 바꾼다.
- 2 3단계 이상 데이터 전달: 값이 세 곳 이상을 거쳐 흐르는 경로를 바꾼다 (예: API 응답 → 스토어 → 화면).
- 3 로직 변경으로 같은 입력의 출력이 달라진다 (분기·계산·순서). 예외: 입력·출력이 같은 로직 변경(리팩터링·이름 정리)은 신호가 아니다. 근거는 둘 중 하나다. (a) 기존 테스트가 그 코드를 덮고 변경 전후 모두 통과한다. (b) 같은 입력으로 변경 전후 출력을 비교한 명령 결과가 같다. 둘 다 없으면 신호로 본다. 근거(돌린 명령과 결과)는 하 일을 끝낼 때 보고와 STATUS 최근 완료 줄에 남긴다.
- 4 약속 변경: 다른 파일·롤이 기대는 함수 모양·공개 형식·이벤트 이름·설정 키를 바꾼다.
- 5 로직이 아니어도 동작이 바뀌는데 테스트가 덮지 않는다.
- 문구·오타·예시·주석·서식·스타일만 바꾸는 일은 파일 수와 상관없이 하다 (파일 6개에 걸친 용어 통일, 뜻 불변). 신호 없는 변경은 5개 이상이어도 하이고, 신호 있는 변경이 5개 이상이면 상이다.

## 2. 스킬·롤 문서 (에이전트가 읽고 따르는 문서)

테스트가 없으므로 신호 5 대신 이 규칙이 우선한다.
- 규칙의 뜻이 그대로인 문구 정리 → 하
- 규칙의 뜻이 바뀜(추가·수정·삭제) → 중
- 등급·검증·배정 흐름을 바꿈(등급표, 하 조건, 사후 점검, 무조건 상 목록, 배정 순서, 평가 절차) 또는 mod 지침(시스템 프롬프트 문구)을 바꿈 → 상
- 뜻이 같은지 애매하면 중
- 예외: 사용자가 승인한 교훈 문장을 그대로 롤 문서에 넣는 일은 하다. 문장이 정해져 판단이 끼지 않기 때문이고, 그 문장이 해당 절에 있는지 grep으로 확인한다. 문장을 바꾸거나 새 규칙을 쓰면 위 규칙대로 정한다.

## 3. 무조건 상 세부

매니저 판단으로 낮추지 않는다. 롤 파일 삭제도 파일 삭제라 상이다. 구조·인터페이스 변경도 상이다. 스킬·롤 문서·war-room 지침·config 수정은 위 2절로 정한다.

## 4. 하 일의 확인과 매니저 직접 처리

- 하 조건 3개는 모두 맞아야 한다. 확인 방법(조건 3)은 돌릴 기계 검사가 있으면 돌리고, 없으면 `git diff`로 바뀐 줄이 요청 범위 안이고 검증 신호가 없는지 본다.
- 담당 롤이 있으면 하라도 그 롤에 맡긴다. 예외 둘: (a) 매니저만 쓰는 파일 (STATUS 정리, 승인된 교훈 넣기). (b) 바꿀 문장·값이 정해진 하 일이고 파일 2개 이하. "정해진"은 사용자가 바꿀 문장·값을 그대로 말했거나 승인했거나, 오타처럼 고칠 답이 하나뿐인 경우다. 판단이 끼지 않아 롤 맥락이 필요 없어서다. 파일 2개 제한은 하 조건의 파일 수가 아니라 롤 없이 매니저가 직접 편집하는 범위를 좁히는 것이다.
- 매니저가 직접 한 하 일은 STATUS 최근 완료에 등급과 바뀐 파일 수를 적고, 신호 3의 예외를 썼으면 그 근거도 적는다.

## 5. 어느 단계를 거치나 (입력마다)

| 입력 | 거치는 단계 |
|---|---|
| 새 요청 | SKILL.md 표대로. 중·상 조건이 둘 다 맞으면 높은 쪽 |
| 롤 없이 직접 하는 일 | 새 요청과 같다. 하가 아니면 평가·검증 에이전트가 판정한다 (매니저 자기 검토 금지. 예외는 SKILL.md "하지 않는 것") |
| 하 일을 끝낸 직후 (사후 점검) | `git diff`에 검증 신호나 무조건 상 조건이 생겼는지 본다. 생겼으면 그 자리에서 그 등급으로 올려 판정한다. 없으면 하로 끝낸다. 파일 수만으로는 올리지 않는다 |
| 평가·검증 보고의 `등급 올림` | 보고가 실제 바뀐 내용의 신호·조건을 보고 등급이 낮았다고 적은 것이다. 올린 등급의 검증을 다시 한다 (중 → 상이면 기준 검토와 사람 승인을 더한다) |
| 사용자가 바꾼 등급 | 위 단계를 건너뛰고 그 등급으로 한다. 예외: 하이면 끝낸 직후 사후 점검은 거친다 (낮춘 등급이 실제 내용과 맞는지 볼 방법이 그것뿐이다). 걸리면 혼자 올리지 않고 알리고 올릴지 묻는다 |
